# 06: Filters as URL params

**What to build:** The board can be filtered by app, project, status set and text (title or description). The filter state is entirely in the URL query string, so a bookmarked URL is a saved view and reload, back and forward all land on the same board. The status set is the whole story of what is on the board: its default is the seven live statuses, so `cancelled` appears only when the filter names it — the `v` view menu keeps only card cosmetics (`app / project`, `updated`). `done` is always in the default set, quiet. `GET /api/tickets` and `GET /api/frontier` accept the same parameters.

**Blocked by:** 04 (Lifecycle — transition table, intent endpoints, drag-and-drop)

**Status:** ready-for-agent

**Decisions (grilled 2026-09-03):**

- *Reversal of 03.* Hiding `cancelled` was a per-device view option; it is now the status Filter. Research: Linear's docs define display options as never hiding issues ("filters will refine the list… display options show all issues in the list but hide or show data on the issue item"), put filters in the URL and view options not, and hide completed/cancelled work with a default *view* (a saved filter); GitHub hides closed issues with the default `is:open` filter in the URL. Neither does what 03 built. A bookmark now shows the same board on every device. CONTEXT.md **View option** rewritten, **Filter** and **Scope** added; spec stories 41/42 and the API-surface line amended; 03's decision line carries the reversal. No ADR.
- *Wire names.* The browser URL uses the API's own names: `app_id`, `project_id`, `status`, `q`. One parser and serialiser in `shared` serves the API (replacing the hand-rolled loop at `api/src/tickets.ts:156`), the web and the CLI. An `app_id`/`project_id` value in the *browser* may be `<slug>-<id>` as routes and `goblin` already write it (`cli/src/args.ts:90`); the web strips the slug before the wire exactly as the CLI does, and the API accepts only an integer id or the literal `null` ("has none").
- *`status`.* Comma-separated, canonical order = lifecycle order. Unknown value → `422` on `path: ['status']`; empty → unset. **API default (absent) is every status**, `cancelled` included — `goblin ticket list` is unchanged. **Board default is the seven live statuses**; the URL carries `status` only when the set differs, so `/?status=cancelled` is one column and checking all eight lists all eight.
- *`q`.* Trimmed; empty → unset. Case-insensitive substring (SQLite `LIKE`, ASCII) over **title or description**, with `%` and `_` escaped so they match themselves. Key lookup is ⌘K's job (10); no FTS.
- *Bad values in a pasted URL* pass straight through: the API answers `422`, the bar shows the problem's message in the refusal line, the board is empty. The address is never rewritten — a bookmark is not silently corrected.
- *Endpoints.* `/api/tickets` gains `status` and `q` (has `app_id`, `project_id`). `/api/frontier` gains `app_id`, `project_id`, `q` through the same parser (`status` is meaningless there). `/api/apps` and `/api/projects` unchanged. `goblin ticket list` gains `--status a,b` and `--q`; `goblin frontier` gains `--app`, `--project`, `--q` (09's rule: every endpoint reachable).
- *Composition.* All parameters AND together; a project outside the chosen app simply yields nothing. Only the statuses in the filter set render as columns (a column you cannot see is not a drop target, by construction); app, project or text alone show every live column, empty ones included.
- *URL is always replaced, never pushed.* Back never steps through filters; leaving and returning restores the URL that was current. The text input writes after 200 ms of quiet; chips write at once. Canonical parameter order `app_id, project_id, status, q`, empties omitted, so equal filters make equal bookmarks.
- *Bar.* Takes the strip between the tile header and the columns (where the view menu renders today). Left to right: `app` chip, `project` chip, `status` chip, the text input, `×` clear. The tile subtitle already counts what is shown. A chip reads its bare label in `--gf-mute` when unset; `app: subway reader` / `status: ready, building` (three or more: `status: 4`) with a `--gf-system` border when set. Mono for keys per DESIGN.md Typography.
- *One picker popover* for all three chips, shaped like Components' **Ticket picker**: chip button → popover anchored beneath. App/project: an input bordered `--gf-system` narrowing rows `any`, `none` (the `null` filter — ideas with no home), then live entries; archived ones hidden unless the URL already names one, shown by name or `#id` if gone. Status: eight check rows in lifecycle order, no input. `↑↓` moves the highlight (raised + system inset), `⏎` picks and closes for app/project, `space`/`⏎` toggles a status row, `esc` closes. Every change writes the URL. Picking a project fills the app; changing the app clears a project outside it (mirrors the Ticket view).
- *Keys.* `f` focuses the text input; `esc` in it blurs without clearing; `×` is click-only (⌘K may grow "clear filters" in 10). DESIGN.md Interaction gains `f` at closeout.
- *`c` on the board* becomes a one-row form under the filter bar: title (focused), app, project, status, `simple`; `⌘⏎` saves, `esc` cancels. Prefilled from the filter (Scope): app and project from their chips; status = the first status in the filter set a ticket may be *created* in (`backlog`…`review`), else `backlog` — the form's status picker offers only those six. Every field is editable before saving; the ticket lands where you sent it, on or off this board. A refusal (approve guard, agent ceiling) shows inline under the row as the API's hint. Replaces 03's title-only input at the top of `backlog`.
- *Entry points.* The `tickets` tile header on the App and Project views gains a `board` link to the board filtered to that app or project. The breadcrumb waits.
- *Not in 06.* Word-AND text matching; a `q` on apps/projects; the collapsed "hidden column" Linear's board has; anything in the URL beyond the four parameters.
