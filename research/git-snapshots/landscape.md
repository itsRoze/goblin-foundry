# Landscape: versioning / checkpointing / provenance for parallel agent work

Researched 2026-08-26. Question: what is the right "git/snapshot/provenance layer" for a Claude Code-centric factory running many agents in parallel — isolation (worktrees), checkpoints, rollback, attribution, and integration back to `main`.

## Notes: which fits a parallel-agent factory

**Isolation: git worktrees, via Claude Code's own `--worktree` / `isolation: worktree`.** Already enforced by the harness (tool calls into the main checkout are blocked; subagent worktrees are locked while running and swept by `cleanupPeriodDays`). `worktree.baseRef: "head"` lets subagents branch from in-flight work; `--worktree "#1234"` branches from a PR. This is the only isolation option that needs zero extra software and is fully headless (`claude -p --worktree`), so it is the default. Caveat: `-p` runs never clean up; the factory scheduler must `git worktree remove` itself.

**Intra-task checkpoints: Claude Code checkpoints are necessary but not sufficient.** They cover only file-tool edits (not Bash `rm`/`mv`/`sed`, not most subagent edits, not symlinks), are per-session, and expire in 30 days. For a factory, add a hook-driven snapshot: a `PostToolUse` hook on Edit/Write/Bash that runs `git add -A && tree=$(git write-tree) && git update-ref refs/factory/<session>/<n> $(git commit-tree $tree -p HEAD -m "turn <n> tool <id>")` and appends `{session, turn, tool_call_id, tree}` to a journal. That gives DeltaDB-style operation-level rewind (`git read-tree` + `checkout-index`) with stable IDs, in plain git, captured regardless of how the file changed. It is the cheapest way to get "code as it was when the agent wrote it".

**jj is the strongest OSS candidate for replacing that hack**, because it *already* snapshots the working copy on every command, keeps an operation log (`jj op log/undo/restore`), gives changes stable IDs that survive rewrites, and stores conflicts as data instead of blocking. Its `workspace` is the worktree equivalent. Costs: Claude Code's worktree enforcement is git-specific (use `WorktreeCreate`/`WorktreeRemove` hooks to substitute `jj workspace add/forget`); jj has no hooks/LFS/submodules; snapshots happen only when a jj command runs (so still wire a `PostToolUse` hook that runs `jj status`); one working copy per workspace means two agents in one workspace collide — always one workspace per agent. agentjj's post-mortem is a useful warning: jj's absorb/squash ergonomics are for humans and can surprise an agent; keep the agent on a tiny vocabulary (`jj new`, `jj describe`, `jj git push`) and let the orchestrator do history editing.

**Attribution: commit trailers now, forge-level provenance later.** Neither Delta nor Origin ships a usable provenance API today. Emulate Origin's announced schema with trailers on every agent commit — `Agent-Session: <claude session id>`, `Agent-Model:`, `Agent-Runner:`, `Agent-Task:`, `Agent-Prompt-Sha:` — plus one GitHub App identity per agent role (scoped, revocable, auditable), and enforce presence in CI. `git blame` -> commit -> trailer -> transcript reproduces DeltaDB's line->conversation link at commit granularity; the journal refs above give it at tool-call granularity.

**Integration to `main`: stacked PRs + a merge queue with an auto-repair agent.** This is the part of Origin's pitch that is real and available elsewhere: Graphite `gt` (or OSS `git-spice`, or jj's native stacking) for small dependent PRs; GitHub merge queue (or Mergify) so dozens of agent PRs land serially with CI green; a queue-failure hook that dispatches a fix-up Claude Code run on the failed PR. Keep GitHub as the system of record — Origin's own beta does.

**Delta and Origin: watch, do not build on.** Delta has the right data model (operation log + conversation in one store, comments anchored to changes, agents read history) but is closed, GUI-first, private beta, undocumented git mapping. Origin has the right *integration* spec (agent principals, provenance, machine-readable review states, agent-aware merge queue) but ships only mirror+PR UI, is closed/hosted with unclear data terms, and privileges Cursor agents. Both confirm the direction; both are vendor traps for a Claude Code fleet right now. Re-evaluate when either publishes an API, a self-host option, or a provenance schema worth adopting as a standard.

**Recommended stack (v1):** git worktrees via Claude Code `--worktree`/`isolation: worktree` -> `PostToolUse` snapshot refs + JSONL journal -> commit trailers for attribution -> stacked PRs (`gt` or `git-spice`) -> GitHub merge queue + repair agent. **v2 experiment:** replace the snapshot hack with jj workspaces via `WorktreeCreate` hooks, keep everything else.
