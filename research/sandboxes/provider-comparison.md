# Cloud sandbox providers — decision matrix for the goblin-foundry factory

- **Type:** comparison (synthesis of round-2 files in this directory)
- **Researched:** 2026-08-26
- **Scope:** exe.dev (round 1), Fly.io Sprites, E2B, Daytona, Modal, Vercel Sandbox, Cloudflare Sandboxes, boxd, Northflank, Morph, Gondolin, rivet sandbox-agent. Per-provider detail and sources live in `sprites.md`, `e2b.md`, `daytona.md`, `modal.md`, `vercel-sandbox.md`, `cloudflare-sandbox.md`, `small-oss-sandboxes.md`, `exe-dev.md`, `exe-dev-factory-series.md`.
- **Workload assumed everywhere:** 10 parallel pi agents, 2 vCPU / 4 GiB each (8 GiB variant noted), 4 h/day x 22 days = **880 sandbox-hours/month**. Costs are list prices as of 2026-08-26, before free credits; "realistic" figures assume the agent is mostly waiting on the LLM (25-30 % CPU duty) where the provider bills active CPU only.

## One-paragraph summary

Every serious option is now a Firecracker/KVM microVM or gVisor container with a TypeScript SDK, sub-2-second start, some form of snapshot, and a hostname/CIDR egress allowlist; the differences that matter for a solo-dev factory are (1) whether there is a **plan floor** (E2B $150, Sprites $20, Vercel $20, Cloudflare $5, exe.dev $20 pooled) versus pure per-second billing (Daytona, Modal, Northflank, Morph), (2) whether you can **fork a running/prepared sandbox 1:N** (E2B, Daytona-VM, Vercel, boxd, Morph; not Sprites, Cloudflare, exe.dev-except-`cp`), (3) whether **secrets can be kept out of the VM** via a proxy (exe.dev, Vercel, Cloudflare, Daytona, E2B workload identity, Sprites connectors, Gondolin placeholders), and (4) **pi support**: pi is preinstalled in exe.dev's exeuntu and Vercel's universal image, has first-party templates/extensions at E2B (`pi` template), Daytona (`@daytona/pi`), Sprites (`pi-sprites`) and Gondolin, and is a one-line `npm i -g` everywhere else.

## Ranking for this factory (solo dev, pi, cloud)

| Rank | Provider | Why | Main caveat |
|---|---|---|---|
| 1 | **E2B** | Best fit to the exact workload: official `pi` template and guide, pause-with-memory + 1:N fork (replaces git worktrees with warm clones), hostname egress allowlist, lifecycle webhooks, Apache-2 self-host escape hatch | $150/mo Pro floor before any compute; idle billed while waiting on the LLM |
| 2 | **Vercel Sandbox** | pi already in the universal image; fork from a golden sandbox; best-documented credential brokering (secrets never enter the VM); active-CPU billing (~$115-170/mo); Vercel's own Eve/Foreman "software factory" templates are the closest prior art | 24 h session cap; managed-only; fs-only snapshots |
| 3 | **Daytona** | Cheapest of the "big" SDK providers on pure usage (~$150/mo, no plan fee), 90 ms starts, `@daytona/pi` extension with branch-per-session sync, placeholder secrets at the egress proxy | Went closed-source 2026-06-11; custom egress lists gated to Tier 3 ($500 top-up); container class = shared kernel |
| 4 | **Cloudflare Sandboxes** | Cheapest with a floor ($5 + ~$85-200), strong VM isolation, programmable egress proxy with credential injection, TS-native, 1,500 vCPU headroom | Disk wiped on every sleep; no snapshot/fork; orchestrator must be a Worker; 1.0 API break imminent |
| 5 | **Fly.io Sprites** | Persistent 100 GB disk, checkpoints/rollback, DNS egress policy, official `pi-sprites` worker-pool extension, realistic cost ~$30-50/mo on the $20 plan | No fork/custom image (must install pi per Sprite), checkpoints are disk-only, no region choice |
| 6 | **exe.dev** | pi preinstalled, cheapest for always-on persistent agents ($20 pooled), edge secret injection, phone/SSH ergonomics; the factory-practice blog series is the best design reference | No egress policy, no SDK (SSH/`/exec` only), no memory snapshot, pooled CPU caps true parallelism |
| 7 | **Modal** | Only option with GPUs + Python-first orchestration, 24 h timeout, CIDR/domain allowlists | Priciest (~$209-334/mo), slowest measured start, memory snapshots experimental |
| -- | **Northflank / Morph / boxd** | Cheapest (Northflank ~$74) or best fork primitive (Morph memory branching, boxd 100-200 ms live fork) | Thin docs / closed source / no egress policy (boxd); revisit when the primary choice's bill or fork latency hurts |
| -- | **Gondolin + rivet sandbox-agent** | Not providers: Gondolin is pi's own OSS micro-VM (placeholder secrets, egress hooks) for a self-hosted KVM box; sandbox-agent gives a uniform HTTP/SSE control plane over pi inside any provider above | Gondolin needs nested virt on the cloud host; sandbox-agent's pi adapter is `default` model only |

**Recommendation:** build the worker layer against a tiny provider interface (create-from-image, exec-stream, put/get files, snapshot, fork, kill, set-egress) modelled on Sandcastle's `SandboxProvider` / Flue's `SandboxFactory`, ship **E2B** first (pi template + fork), keep **Vercel Sandbox** as the second implementation (pi already in-image, secrets brokering), and treat exe.dev as the persistent "long-lived bot" tier rather than the per-task worker tier. Push LLM/GitHub credentials through the provider's egress proxy wherever it exists (Vercel firewall transforms, Cloudflare outbound proxy, Daytona `dtn_secret_*`, E2B workload identity, exe.dev integrations) so a compromised agent never holds a real key.

## Notable techniques worth stealing (cross-provider)

- **Golden snapshot + fork per task** (E2B `fork`, Vercel `Sandbox.fork`, Daytona VM `fork`, boxd live fork, Morph Infinibranch): clone the repo and warm the package cache once, fork N times; replaces git worktrees and cuts create+`npm install` from ~16 s to <1 s (Vercel's own numbers).
- **Secrets injected at the network edge** (exe.dev integrations, Vercel credential brokering, Cloudflare outbound proxy, Daytona placeholders, Gondolin placeholder secrets, Sprites connectors, E2B SPIFFE tokens): agent code sees a placeholder or nothing.
- **Deny-all egress + explicit allowlist** of `api.anthropic.com`, `github.com`, `registry.npmjs.org` (E2B `allowOut`, Vercel firewall, Cloudflare `allowedHosts`, Modal domain allowlist, Sprites DNS policy, Daytona domain list).
- **Pause-on-timeout, auto-resume on next call** (E2B `lifecycle.onTimeout:'pause'` + `autoResume`, Vercel auto-snapshot on stop) so a stalled agent costs nothing and can be resumed with its context.
- **Worker pools driving `pi -p` over stdin/RPC** (superfly/pi-sprites, Modal `sandbox_pool.py`, Daytona `@daytona/pi`): one pool controller, many sandboxes, auto-checkpoint after each turn.
- **Sessions JSONL as the artifact**: pi's `~/.pi/agent/sessions/*.jsonl` survives pause/snapshot everywhere; copy it out (`files.read`, `scp`, R2 backup) for provenance and review.
- **Merge queue instead of CI + cascading agent review** (exe.dev series): failures land back in the live agent context; human reads reviews, not code.

## Weaknesses / open questions / risks

- Cost estimates are list-price arithmetic; nobody has measured our real duty cycle. Instrument the first week (provider lifecycle webhooks / `getMetrics`) before committing to a plan tier.
- Daytona's closed-source pivot and Cloudflare's 1.0 API break show provider churn; the provider-interface abstraction is the hedge.
- Firecracker providers cannot bind-mount a local checkout (Sandcastle's research): every cloud path needs git bundle/patch or push/pull sync — decide early whether workers push branches (Daytona/OpenCode `opencode/N` pattern) or the orchestrator pulls diffs (Cloudflare example `git diff`).
- Independent cold-start and reliability benchmarks (LogRocket 2026-08, Ry Walker, Northflank) disagree with vendor claims by 2-10x; only Modal's and Vercel's own measured numbers were found.
