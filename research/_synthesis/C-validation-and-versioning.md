# Synthesis C — Validation (oracles, gates, evals) and Versioning (snapshots, provenance, integration)

Scope: every file in `research/validation/` (4) and `research/git-snapshots/` (8). Decisions assumed: runtime = pi, solo dev, one cloud VM per agent, open source. Date: 2026-08-26.

---

## 1. What we now know

1. **"Done" is a stack of oracles ordered by cost and by how hard they are to fool; only deterministic checks may block.** Build/typecheck/lint/tests/diff-coverage/mutation/arch rules block; LLM graders rank and filter; held-out checkpointed evals judge the *harness*, not the PR. `[validation/validation-landscape.md]`
2. **Agent-written tests mostly cannot fail.** 80.2% of agent test patches carry weak or no oracle signal (All Smoke, No Alarm); 23.8% of "successful" repair rollouts rest entirely on non-bug-discriminating tests (BSG-VA); agents pass coarse mutation checks far more often than rubric checks (SWE Atlas). The gate must check *that tests can fail*, not that they pass. `[validation/validation-landscape.md]`
3. **Two cheap "tests can fail" proxies exist besides full mutation:** the no-op stub check (hollow out the function under test; agent's tests must go red) for test-writing tasks, and B/S/G replay (run new tests on the pre-fix commit; ≥1 must fail there) for bug-fix tasks — both seconds, both binary. Feeding the B-replay result back to the agent gave +7.4pp. `[validation/validation-landscape.md]`
4. **Mutation is affordable only when incremental and scoped to the diff.** Stryker `--incremental --mutate <file>` with `thresholds.break`, mutmut cache + `--CI`, gremlins `--threshold-efficacy`, mutate4go's embedded footer manifest — every serious tool has a differential mode and a non-zero-exit score gate. Budget it pre-merge on changed files and nightly for the full run, never per tool-call. `[validation/validation-landscape.md]` `[validation/unclebob-acceptance-and-quality-tools.md]`
5. **Uncle Bob's per-file zero-survivor rule beats a global percentage** ("Only start the next file when the current file has no uncovered mutations and no survivors") because a percentage is gameable by adding easily-killed code; combine with `--scan` mutation-site count (>50 sites → split file) as a size smell. But **every one of his repos has no LICENSE** ("All rights reserved") — cannot be vendored into an OSS factory. `[validation/unclebob-acceptance-and-quality-tools.md]`
6. **Acceptance-data mutation is a distinct, language-neutral oracle:** APS mutates Gherkin *example values* in the JSON IR (never source) and demands the acceptance test fail — proves E2E tests are wired to the app; sidesteps equivalent-mutant noise; ~500 lines to reimplement; runner-worker is a persistent NDJSON process. `[validation/unclebob-acceptance-and-quality-tools.md]`
7. **Uber's production gate ordering is build → run → coverage-or-scenario delta → conventions → mutation → lint → splice**, with a "do no harm" Fixer (reversible patches, revert if passing tests degrade, freeze chronic non-improvers). Admission test for a generated test: it must raise line coverage *or* satisfy a named scenario, else revert. `[validation/uber-autocover-ureview-mechanics.md]`
8. **LLM review only became trustworthy as a chain, not a prompt:** generate → *second model* grades with confidence → per-(assistant, language, category) thresholds → semantic dedupe → category suppression → post. Best pair on the golden set was Claude-4-Sonnet generator + o4-mini-high grader (different vendor). "Addressed" is measured by re-running the reviewer 5× on the final commit. Results: 75% useful, 65% addressed. `[validation/uber-autocover-ureview-mechanics.md]`
9. **SlopCodeBench already ships a `pi` adapter** (`configs/agents/pi.yaml`, `pi --print --mode ... --no-session`, `extra_args` for `--extension`), so benchmarking our harness costs zero adapter work. It provides checkpointed specs, hidden black-box pytest oracles, cumulative regression (ck N replays 1..N-1), CORE/FUNCTIONALITY/ERROR/REGRESSION markers with pass policies, quality trajectories, and canary strings. No model solves any problem end-to-end (best checkpoint 17.2%). Python-only, hours per run. `[validation/slopcodebench.md]`
10. **ECLoop-style evidence gates (deny `edit` until required `read`s happened) improve results and cut tokens** (+4.8–11.8pp Pass@1, −12% tokens) — implementable as a ~100-line pi `tool_call` hook; same hook family enforces "verify hash == HEAD before commit" and "no `tests/**` writes in fix tasks". `[validation/validation-landscape.md]`
11. **Per-VM isolation makes worktrees and jj workspaces moot.** Every worktree orchestrator assumes a shared checkout on one machine — the thing we removed. Keep only conventions: `agent/<task-id>` branch from fresh base, task metadata in PR body, TTL sweeper. `[git-snapshots/worktree-orchestrators.md]` `[git-snapshots/jujutsu.md]`
12. **jj inside the VM gives tool-call-granular, undoable checkpoints with no custom format:** working copy = commit, op log records every command, `jj op restore <op>` rolls back anything, `jj util snapshot` from a pi `tool_result` hook, op ID stored as a pi session entry so `/fork` + `op restore` rewind code and conversation together. Costs: no hooks/LFS/submodules; snapshot only on command; op-store growth at thousands of ops/day untested; agentjj post-mortem shows `absorb`/`squash`/colocated-`git` confuse agents. `[git-snapshots/jujutsu.md]` `[git-snapshots/landscape.md]`
13. **Provenance must live in commit trailers and the PR body, not change IDs:** jj change-ID headers do not survive `git rebase`/squash by the merge queue; the squash message must copy `Agent-Session/Agent-Model/Agent-Task/Agent-Prompt-Sha/Agent-Runner` from a PR template. pi exports `PI_SESSION_ID`, `PI_MODEL`, `PI_SESSION_FILE` to bash children, so jj `templates.commit_trailers` can read them. `[git-snapshots/jujutsu.md]` `[git-snapshots/stacking-and-merge-queues.md]` `[git-snapshots/landscape.md]`
14. **Both "agent-native VCS" products are vendor traps today.** Zed DeltaDB (operation-level CRDT deltas + messages in one log) is private beta, closed, no API, git mapping undocumented; Cursor Origin's agent-native features (provenance, agent principals, machine-readable review state, agent-aware merge queue, stacks) are announced, not shipped. Both confirm the direction; every piece is emulable on git + pi session + trailers. `[git-snapshots/zed-delta.md]` `[git-snapshots/deltadb-data-model.md]` `[git-snapshots/cursor-origin.md]`
15. **Integration is free and native on GitHub in 2026:** merge queue (GA; CI on `merge_group`; `gh pr merge --auto`; `dequeued` event → repair loop) and stacked PRs (`gh stack`, public preview 2026-07-30, `gh stack merge` lands every layer below in one op). OSS `git-spice` (`gs stack submit --fill --no-prompt`) is the scriptable stacking CLI; Graphite is now Cursor-owned. GitHub's queue is FIFO/no batching — Mergify only if >~20 PRs/hour. `[git-snapshots/stacking-and-merge-queues.md]`
16. **ACP is the wrong protocol for orchestration but the right event shape.** pi is not native ACP (Discussion #4444 open; `pi-acp` community adapter lacks `request_permission`); pi's `--mode rpc` is richer (steer/fork/tree). But ACP's `tool_call{kind,status,locations,content:[diff]}` schema is a good neutral format for the factory's event log, and later lets a human attach Zed/JetBrains to a VM's agent. `[git-snapshots/acp.md]`

## 3. Tensions & tradeoffs

- **Mutation cost vs signal.** Mutation is the strongest deterministic oracle but "minutes–hours, CPU-bound"; SCBench runs take hours; TS monorepos need per-package Stryker configs. Resolution in evidence: incremental + diff-scoped pre-merge, full nightly, and the two 5-second proxies (stub check, B/S/G) inside the loop. Residual tension: equivalent mutants force a <100% threshold, which agents game by adding easy code — hence per-file zero-survivor on *new* functions rather than a global score. `[validation-landscape]` `[unclebob]`
- **jj vs plain git.** jj gives op log, undo, stable change IDs, conflicts-as-data "with zero custom format"; git `write-tree` journal gives 80% of that with zero new dependency and no failure modes. Evidence against jj: no hooks (all policy must live in pi extensions), snapshot only on command, agentjj's post-mortem (absorb/squash/colocated `git` bit agents), multi-workspace hangs, untested op-store growth at thousands of ops/day, change IDs lost through GitHub squash. Landscape's own call: git v1, jj v2 experiment. `[jujutsu]` `[landscape]`
- **Per-VM isolation makes worktrees moot — but also removes jj's best feature.** Workspaces, conflicts-as-data across agents, and geirsson-style merge skills only help when agents share a repo store; they don't. What remains valuable is single-agent undo/snapshot. Worktree orchestrators' review surfaces (ensemblr, coppice) can't attach to a remote VM without an ACP/pi-server bridge. `[worktree-orchestrators]` `[jujutsu]` `[acp]`
- **LLM grader vendor diversity vs simplicity.** Uber's evidence: the best F1 came from a different-vendor grader (Sonnet + o4-mini), and graders drift on model updates (keep a golden set). For a solo dev this means two API accounts and a 30–50 PR golden set to maintain, versus a single Anthropic-only chain that "shares blind spots with the author model." `[uber]` `[validation-landscape]`
- **Held-out evals vs in-repo tests.** Held-out tests are the only oracle "fooled by nothing cheap", but hiding tests from the worker means the worker cannot run them in its inner loop, so it iterates blind on the external contract; SCBench-style problems "take ~40 hours to solve well" to author. In-repo tests are fast but agents edit them to pass. Resolution: both — in-repo for the inner loop with `tests/**` write policy; held-out cumulative acceptance in the orchestrator as the definition of done. `[slopcodebench]` `[validation-landscape]`
- **Gate strictness vs Fixer loops.** Uber bounds repair (retries per test case, freeze chronic non-improvers, revert on regression); without bounds, a strict gate turns into an infinite cost sink. AutoCover's viable-test rate is only 20% for Java — expect most agent test candidates to be rejected. `[uber]`
- **Provenance fidelity vs merge strategy.** Squash-merge (simplest for queue) destroys per-commit trailers and jj change IDs; rebase-merge keeps them but keeps agent noise commits. Chosen tradeoff: squash + PR-body template that carries trailers; tool-call granularity lives in the journal/session, not in git history. `[stacking-and-merge-queues]` `[jujutsu]`
- **Licence vs quality of Uncle Bob's tools.** The most agent-oriented mutation/quality tooling (SKILL.md per tool, differential footer manifest, acceptance mutation) is "All rights reserved"; the OSS alternatives (Stryker/mutmut/gremlins) lack the agent workflow text. Port the workflow text, not the code. `[unclebob]`
- **Review chain precision vs volume.** uReview's per-category thresholds and suppression lists were tuned from ~65k diffs/week of votes; at solo scale only a global threshold and a small golden set are realistic. `[uber]`
- **Free native GitHub (FIFO queue, preview stacks with no API) vs SaaS (Graphite/Mergify).** Native is enough until ~20 PRs/hour; Graphite is now Cursor-owned, doubling lock-in. `[stacking-and-merge-queues]`

## 4. Open questions to resolve before a blueprint

1. **Measured cost of `verify:deep` in our VM:** wall-clock and $ for Stryker `--incremental` (TS), mutmut (Py), gremlins (Go) on a representative 300-line diff at 4/8 vCPU — landscape admits "no hands-on run… thresholds are vendor defaults." Decide the pre-merge time budget (10 min?) from data.
2. **jj op-store behaviour at ~2,000 snapshots/day/agent:** growth, `jj op abandon` policy, hang reports — run a 24-hour soak in one VM before committing to jj as v2.
3. **Colocated or non-colocated jj in the VM?** Colocated keeps `git`/`gh` tooling working but triggers the agentjj "files deleted in index" confusion; non-colocated needs every git-facing step to go through `jj git`. Also: does pi's bash tool policy (regex deny on `absorb|squash|abandon|op restore|git push`) suffice?
4. **Does jj `templates.commit_trailers` accept `env()` in v0.44?** The research note says "exact template functions vary by version." Verify, else fall back to `--config` per invocation from the orchestrator.
5. **Which no-op stub / B/S/G implementation for our languages?** SWE Atlas harness and rubric files were not inspected; need a ~50-line script per language (TS: replace function body with `throw`; Py: `raise NotImplementedError`) plus a test-manifest format the worker must emit.
6. **Weak-oracle AST rule:** eslint rule vs ruff plugin vs standalone; exact allowlist of "value-comparing" assertion forms per framework (vitest/pytest/go testing).
7. **Held-out acceptance mechanics:** where do hidden tests live (orchestrator repo? separate private repo with canaries?), how are they executed against the worker's VM (ship the built artifact out, or ssh tests in?), and how is the CORE/REGRESSION marker scheme expressed in vitest/go test (pytest markers exist; others don't).
8. **SCBench private-problem path:** `docs/problems/tutorial.md` and "point runner at a private checkout" unverified; Python-only env — do we author a `docker-node` environment, and how many hours/$ is one weekly run of 3 problems × pi?
9. **Grader vendor:** does a Haiku-class Anthropic grader lose enough F1 vs an OpenAI-class one to justify a second vendor? Needs the 30–50 PR golden set first — who labels it (solo dev)?
10. **Provenance schema names:** freeze trailer keys now (`Agent-Session`, `Agent-Model`, `Agent-Task`, `Agent-Prompt-Sha`, `Agent-Runner`) or wait for Origin/ACP to publish a de-facto standard? Decide policy: freeze, and rename via CI mapping later.
11. **Merge strategy:** squash (trailers via PR body) vs rebase (per-commit trailers survive). Also whether `gh stack` interacts with merge queue at all (undocumented) — if not, `git-spice` + queue is the only tested path.
12. **Repair loop budget:** retries per dequeue (3 proposed), whether repair resumes the same VM/session (state might be swept by TTL) and what "Needs You" looks like for a solo dev.
13. **Event log format:** normalise pi `tool_execution_start/end` to ACP `tool_call` JSON now (cheap) or keep pi-native and convert at the review-UI boundary?
14. **APS reimplementation vs asking for a licence:** one email to Uncle Bob could unblock vendoring; otherwise budget ~500 lines for Gherkin→IR→value-mutator in TS.

## 5. Cross-links

- **Runtime / sandbox (pi, VMs):** every blocking gate is a pi `tool_call`/`tool_result` extension (verify-hash-before-commit, `tests/**` deny, ECLoop read-before-edit, jj snapshot on `tool_result`, bash-verb allowlist for jj/git); pi env vars `PI_SESSION_ID`/`PI_MODEL`/`PI_SESSION_FILE` are the provenance source; pi `--mode rpc` `fork`/session entries carry the checkpoint op ID; pi `--print --no-session` is what SCBench drives. Mutation and nightly suites need VM CPU budgeting (`--max-workers`/`--concurrency` ≈ vCPUs) and a warmed base image (worktree-orchestrators' `node_modules` symlink analogue). Held-out acceptance needs a way to run tests *against* a VM from outside it.
- **Control plane / process:** the orchestrator, not the model, owns history reshaping (`gs stack submit`, `jj bookmark`/push, squash, `gh pr merge --auto`), the held-out test store, `verify.json` parsing, the AO-style state machine (Working → Needs You → In Review → Ready to Merge), dequeue→repair re-dispatch to the same session, TTL sweeping of branches/VMs, and the weekly SCBench harness-CI job with strict-pass/erosion alarms. The review chain is a second pi session the control plane schedules per PR. Per-role GitHub App identities are a control-plane secret-management concern.
- **Field lessons:** Dex Horthy's "lights-off bar ≥80%" and "LLM judge as report, not gate"; Uncle Bob's "don't read, constrain"; Uber's "unfiltered outputs led to hallucinated issues" and "async agents are only useful if developers can trust what they come back with" (Cognition); agentjj's "jj solves human problems" really meaning "don't give agents history-editing verbs"; Vibe Kanban's sunset and Graphite's acquisition as warnings against depending on the orchestrator/forge SaaS layer; exe.dev's "the merge queue *is* the CI."
