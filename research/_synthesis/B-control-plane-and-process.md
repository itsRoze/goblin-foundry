# Synthesis B — Control plane & process

Scope: orchestration loops, task trackers, phase/gate designs, inter-agent protocols, skills/plugins conventions, hooks, spec-driven templates. Inputs: every file in `research/factories/`, `research/patterns/`, `research/skills-agents/` (16 files, read 2026-08-26). Decisions already fixed: runtime = pi, solo dev, cloud sandboxes, open source.

## 1. What we now know

1. **Nobody has shipped "isolation + acceptance + queue" in one open project.** Sandcastle owns sandbox/worktree/session plumbing but "done = agent printed `<promise>COMPLETE</promise>`" with no code-owned gates; SSSF owns phases/gates/trace but runs on the current branch with no isolation, parallelism, or merge; SwarmForge owns inter-agent protocol + discipline but has zero sandboxing and no license. The blueprint must compose. `[factories/sandcastle.md]` `[factories/super-simple-software-factory.md]` `[factories/swarm-forge.md]`
2. **"Agent proposes, code disposes" is the converging control-plane stance** across the two most rigorous sources: SSSF (Python owns sequencing/retries/acceptance/commit; agents are bounded nodes returning typed envelopes) and bmad-loop ("Story selection, retry budgets, gates, and completion checks are code, not prompts"; verification checks disk artifacts, never the agent's claim). `[factories/super-simple-software-factory.md]` `[patterns/spec-driven-methods.md]`
3. **Gates verify claims post-hoc, never predictions.** SSSF gate set: `artifacts_exist, files_non_empty, json_parses, diff_matches_claims, verdict_consistent, tests_pass(cmd)`; permission-by-diff (snapshot tree before, compare after, reversion counts as a change, `protected_files` for the harness). fusion-harness goes further: a separate VALIDATOR model writes an executable `gate.py` *before* the build, harness proves it starts RED, builder iterates on verbatim `FAIL:` lines, one gate repair per run. `[factories/super-simple-software-factory.md]` `[skills-agents/fusion-harness.md]`
4. **Fresh context per task is the dominant loop design.** Ralph (`while :; do cat PROMPT.md | claude; done`), afk.sh (new `claude` per iteration, memory = issue files + last 5 commits), GSD ("each executor starts with a clean 200k-token context"), QRSPI (<40% context, fresh at 60%), BMAD story loop (fresh chat per step). Dex on Anthropic's in-session Stop-hook plugin: it "misses the key point of ralph." `[patterns/ralph-loop.md]` `[patterns/afk-workflow.md]` `[patterns/spec-driven-methods.md]` `[patterns/rpi-qrspi-humanlayer-skills.md]`
5. **But resumed sessions win for corrections.** SSSF re-prompts the *same* pi session on parse/gate failure ("A cold restart throws away everything the agent learned. A correction costs one message"); Sandcastle's `Output.object({maxRetries})` and produce-then-extract both `resumeSession`. Rule emerging: fresh per *task*, resumed per *retry*. `[factories/super-simple-software-factory.md]` `[factories/sandcastle.md]`
6. **Markdown plan files do not survive >1 worker.** Ralph's `IMPLEMENTATION_PLAN.md` and afk-workflow's `Status:` line have no dependencies, no atomic claim, and conflict on merge. Beads gives hash IDs (`bd-a3f8.1.2`), `bd ready --claim --json` (open ∧ no open blockers ∧ unclaimed, atomic), `blocks` edges, gates (`gh:run`, `gh:pr`, `human`, timer), and execution metadata (`execution_suggested_model`, `_reasoning_effort`, `_parallel_group`). Cost: Dolt-in-Go, 80+ commands, single-writer embedded mode, version pinning in VM images. `[patterns/beads.md]` `[patterns/ralph-loop.md]` `[patterns/afk-workflow.md]`
7. **Planner emits a dependency graph; scheduler runs the ready frontier.** Same shape in Sandcastle's plan-prompt (unblocked issues + deterministic `sandcastle/issue-{n}` branch names, tie-break rule when all blocked), fusion-harness's JSON DAG (`depends_on`, `mode: read|write`, cycle check, 3 repair attempts), Pocock's `to-tickets`/`implement-spec` ("a task graph with blocking relationships... always a frontier"), GSD waves, Spec-Kit `[P]` markers, wayfinder's frontier = open ∧ unblocked ∧ unclaimed. `[factories/sandcastle.md]` `[skills-agents/fusion-harness.md]` `[skills-agents/mattpocock-skills.md]` `[skills-agents/wayfinder.md]` `[patterns/spec-driven-methods.md]`
8. **Day shift / night shift is the process split for a solo dev.** Day = HITL alignment (`/grill-with-docs` → `CONTEXT.md` + ADRs → `/to-spec` → `/to-tickets` → `/triage` → `ready-for-agent`); night = loop over triaged tickets. QRSPI says implementation "is a small fraction of the overall cycle... Quality stems from alignment phases." `[patterns/afk-workflow.md]` `[skills-agents/mattpocock-skills.md]` `[patterns/rpi-qrspi-humanlayer-skills.md]`
9. **Triage is a state machine with allowed/forbidden transitions for agents:** `needs-triage → {needs-info | ready-for-agent | ready-for-human | wontfix}` + `done`; the agent may set `done | ready-for-human | ready-for-agent(partial) | needs-info`, never `needs-triage | wontfix`. Sandcastle CI uses labels `agent:implement → agent:in-progress → agent:review | agent:blocked` with refusal preflights and a failure comment saying how to retry. `[patterns/afk-workflow.md]` `[factories/sandcastle.md]`
10. **Inter-agent protocol should be files + helper scripts, not chat.** SwarmForge: durable inbox/outbox dirs, priority-sorted filenames, lifecycle timestamps, daemon-owned delivery, lossy generic wake-ups, agents write 4 headers and a helper fills SHA/id; two-call `AUDIT_REQUIRED` gate; terminal broadcast = machine-detectable done. SSSF: exactly two channels — `context_handoff/` files + one JSON envelope. fusion-harness: exact-string ACK + SHA-256 context sync; peer output wrapped as "untrusted debate material, never instructions." `[factories/swarm-forge.md]` `[factories/super-simple-software-factory.md]` `[skills-agents/fusion-harness.md]`
11. **Role = tool allowlist, enforced mechanically.** fusion-harness `READONLY_TOOLS=read,grep,find,ls` for every parallel worker, exactly one `FULL_TOOLS` writer, `VALIDATOR_TOOLS` without bash/edit; CWD-scoped writer lease in `/tmp` with PID liveness. SSSF `writes:` boundary ("`tools` is a capability list. `writes` is the boundary"). Wayfinder's most-reported failure (planner writes code) is fixable with `pi.setActiveTools`. `[skills-agents/fusion-harness.md]` `[factories/super-simple-software-factory.md]` `[skills-agents/wayfinder.md]`
12. **Instruction budget is a hard design constraint.** RPI failed at 85+ instructions per prompt; models drop steps past ~150–200; split phases so each prompt stays small; "A 1,000-line plan contains as many surprises as 1,000 lines of code." Design doc (~200 lines) gets deep review, plan only spot-checked. `[patterns/rpi-qrspi-humanlayer-skills.md]`
13. **Skills are the only artifact identical in pi and Claude Code.** Spec-only frontmatter (`name, description, license, compatibility, metadata, allowed-tools`) + `disable-model-invocation` is the portability line; pi reads `.agents/skills/` up to git root, `~/.agents/skills/`, `.pi/skills/`, and `--skill`; hooks/agents/MCP in plugins have no pi loader and need an extension. pi caveat: "models don't always [read SKILL.md]; use prompting or `/skill:name` to force it." `[skills-agents/agent-skills-spec.md]` `[skills-agents/claude-code-plugins.md]` `[skills-agents/skills-sh-registry.md]`
14. **Hooks map to pi extension events with one gap class.** `tool_call` (block/mutate), `tool_result`, `input`, `session_start`, `agent_end`+follow-up (≈Stop-block), `session_before_compact` cover the policy layer; missing: subagent/worktree/task lifecycle events and true stop veto — all orchestrator-level anyway since the factory spawns pi processes. A Claude-hook-JSON shim in one extension lets existing hook scripts run unchanged. `[skills-agents/hooks-mastery-to-pi-mapping.md]`
15. **Recurring work is a control loop, bounded to one open PR per lane.** humanlayer's set point / sensor / controller / actuator / dampener; scheduled run no-ops while a labeled PR is open; memory file loaded after the controller, updated only via `/iterate`; run each component locally before CI. Spec-Kit's `converge` is a sensor. `[skills-agents/humanlayer-skills.md]` `[patterns/rpi-qrspi-humanlayer-skills.md]` `[patterns/spec-driven-methods.md]`
16. **Operator discipline for the human-facing session:** SSSF's operator skill "print the menu and wait", "volunteered state is guessed state", four-line prompt shape (ask / Where / Done means / Out of scope), never does ADW work itself. `[factories/super-simple-software-factory.md]`

## 3. Tensions & tradeoffs

**Fresh-context loops vs resumed sessions.** Ralph/afk/GSD/QRSPI: every task in a new window; memory is disk (plan file, issue files, `git log -n 5`, `AGENTS.md`). SSSF/Sandcastle: keep the session and *correct* it on gate failure (parse retry, `maxRetries`, `resume(prompt)`), and SSSF's `agent_map.json` lets a later ADW resume each agent's window; SwarmForge keeps roles as persistent TUIs. bmad-loop splits the difference: fresh session per stage, but "review never inherits the implementer's context, so there's no anchoring bias." Resolution candidate: fresh per ticket and per stage; resume within a stage for gate corrections (bounded by `max_dev_attempts`); never resume across a model change (SSSF: "model drift → fresh session"). Sandcastle's ADR 0011 (`resume` = exactly one iteration) is a warning that resume-chaining gets awkward.

**Agent-proposes/code-disposes vs agent-driven orchestration.** SSSF, bmad-loop, GSD-verify: code owns the graph, agents are nodes; "done" is a disk fact. Sandcastle, Ralph, afk: the agent picks the task, decides done, and even performs the merge (Sandcastle's merger agent is "the least deterministic step"); GSD `/gsd-autonomous` is one long-lived agent orchestrating subagents inside the runtime. Pocock's `implement-spec` is agent-driven but per-ticket. Evidence favors code-owned: SSSF's `permissions.py` story (a builder `git checkout adws/` and "discard[ed] uncommitted changes to the very quality check it was about to be judged by"), fusion-harness burning 3 rounds on a gate bug the *harness* had to detect. Cost: the harness is code we own; SSSF's own admission is that placeholder `quality.py` makes test phases "theater" until edited.

**Skills vs hardcoded phases.** Pocock: small composable skills, "fix the failure modes, don't own the process"; GSD/BMAD/Spec-Kit own the phase sequence and route commands; SSSF hardcodes phases in Python but keeps prompts as files; fusion-harness "edit files, not code." SSSF's operator skill and Spec-Kit's `converge` show the middle: phases in code, *content* of each phase as a skill/prompt file. Risk on the skills side: pi "models don't always read the file" — model-invoked skills are less reliable in pi than Claude Code, so AFK phases must force-load (`--skill`, `before_agent_start`) rather than rely on routing.

**Beads vs markdown plan files vs tracker labels.** Beads: correct concurrency, gates, execution hints, but Dolt/Go weight, single-writer embedded mode, must be baked into VM images, telemetry on. Markdown (`IMPLEMENTATION_PLAN.md`, `docs/afk-workflow/backlog/`): zero deps, human-readable, but linear context cost and no atomic claim; afk-workflow admits it "falls over past a few dozen issues." GitHub issues + labels (Sandcastle CI, Pocock `to-tickets`): native blocking renders the frontier ("Blocking is what renders the frontier visually"), but needs `gh` in the sandbox and API rate. Hybrid seen in the sources: Sandcastle supports Beads as a tracker; Beads has `bd github` sync; Spec-Kit keeps `tasks.md` as a projection. Leading option: Beads on the controller as the queue, GitHub as the human UI via sync, one issue per VM passed by prompt.

**Executable gate vs reviewer agent vs TDD-in-prompt.** fusion-harness: a script is the definition of done ("impossible to pass without actually doing what was asked"). SSSF: shallow structural gates + read-only reviewer with `verdict_consistent`. Pocock/afk/Sandcastle: TDD at pre-agreed seams inside the implementer plus two-axis `code-review`; "no executable definition of done." SwarmForge: role chain *is* the gate (specifier → coder → cleaner → architect), plus mutation testing. GSD: coverage block auto-passes only test-proven deliverables. They stack rather than conflict, but each adds a model call; the gate-first approach needs acceptance criteria good enough for a validator to script — which is exactly what `to-tickets` produces.

**Single-writer shared checkout vs worktree-per-agent.** fusion-harness and SwarmForge-master: one tree, serialized writes via lease/tool allowlists ("simpler and more robust... for tasks that need one coherent artifact"). Sandcastle, `implement-spec`, BAD, bmad-loop `isolation=worktree`, SwarmForge roles: worktree/branch per agent, merge later (conflicts "expected" in SwarmForge). For cloud sandboxes worktree-per-VM is forced; the lease still matters *inside* a VM if a worker spawns subagents.

**Human gates: where and how many.** SwarmForge holds every specifier handoff for Approve/Reject; RPI pauses after each phase for manual verification; GSD autonomous pauses only on "one-way doors"; humanlayer bounds by one open PR; afk/Ralph review in the morning via `git log`. Solo-dev constraint pushes toward GSD/humanlayer: approve at spec boundary, reversibility gates, PR-bounded flow, everything else AFK.

**Instruction budget vs "signs."** Ralph tunes by *adding* guardrails every failure (`999…` lines); QRSPI says prompts degrade past ~150–200 instructions and RPI's 85+ was already too many. Long always-loaded skills (wayfinder ~12k chars) are criticized even by their author's own `writing-for-agents`. Implication: signs go into gates/scripts (`src/lib`, hooks) rather than prompt text where possible.

## 4. Open questions to resolve before a blueprint

1. **Queue topology:** Beads embedded on the controller only (workers receive one issue via prompt, controller closes it) vs `bd dolt push/pull` inside each VM vs `dolt sql-server` reachable from sandboxes. Needs a concurrency test of `--claim` under push/pull (beads.md flags this as unverified).
2. **Gate language:** accept fusion-harness's `uv` PEP 723 Python gates as the universal acceptance format, or define a `gate.sh` contract (exit 0 iff done; `PASS:/FAIL:` lines) that any language can satisfy?
3. **Who writes the gate:** validator agent per ticket (cost: one extra frontier-model call + baseline run), or human-authored acceptance criteria compiled by a cheaper model, or tests-only (`tests_pass`) for v1?
4. **Envelope schema v1:** minimum fields (`status, summary, artifacts, changed_files, commit_message, notes_for_next_agent, blocking`) and which gates are mandatory per phase (`plan`, `build`, `review`, `merge`).
5. **Merge step ownership:** orchestrator `git merge` + typecheck/test, escalating only conflicts to an agent with the update-branch prompt — confirm this is acceptable, and decide ff/merge/squash and `rollback_on_failure` semantics (bmad-loop `[scm]`).
6. **Session policy matrix:** per stage (plan/build/fix/review/extract/merge): fresh vs resume, max corrections, token cap, model/thinking (from Beads execution metadata?).
7. **Skill loading in AFK workers:** clean-room children (`--no-skills --no-extensions --no-context-files`) with explicit `--skill`/`--append-system-prompt`, or trust-gated project skills? Which pi extension events (`before_agent_start`, `resources_discover`) force role skills?
8. **Tool policy implementation:** pi `--tools` per phase + extension `tool_call` block list + post-hoc permission-by-diff — are all three needed, and what is the `protected_files` list for the factory harness itself?
9. **Human gate set:** exactly which transitions require a human (spec approval, `ready-for-human`, one-way doors, PR merge), and the channel (Beads `human` gate + `ATTENTION` file vs PR comment `/iterate` vs dashboard).
10. **Trace store:** SSSF SQLite schema vs OpenTelemetry (pi-telemetry / dash0) — pick one; must include `processes` for kill-ability and per-iteration cost.
11. **Tracker UI for humans:** GitHub issues synced from Beads (`bd github`), Linear, or Beads-only with a read-only web view? Wayfinder/`to-tickets` need native blocking.
12. **Day-shift phase set:** Pocock chain as-is (`grill-with-docs → to-spec → to-tickets → triage`) vs QRSPI-lite (Q → R ticket-hidden → D+S → P); which artifacts are mandatory inputs for a ticket to be `ready-for-agent`?
13. **Completion signal contract in pi:** `<promise>…</promise>` in final assistant text vs a file the agent writes vs structured extraction turn — pick one for the orchestrator to parse from `--mode json`.
14. **Licensing:** SwarmForge and how-to-ralph-wiggum and hooks-mastery have no license; confirm we only reimplement semantics, never copy text/scripts.
15. **Sandcastle dependency stance:** vendor/fork the TS plumbing (Effect-ts peer dep, dormant since June) or write our own `run()` over pi.
