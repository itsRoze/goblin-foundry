## Body of work relevant to a Claude Code–centric factory

### 1. 12-Factor Agents (Apr 2025)
https://github.com/humanlayer/12-factor-agents (short link https://hlyr.dev/12fa) — 25.5k stars. Principles for production LLM software; the ones that matter most for coding-agent orchestration: F2 own your prompts, F3 own your context window, F5 unify execution and business state, F6 launch/pause/resume with simple APIs, F7 contact humans with tool calls, F8 own your control flow, F9 compact errors into context, F10 small focused agents, F12 make your agent a stateless reducer. Core framing reused everywhere later: "LLMs are stateless functions... the contents of your context window are the ONLY lever you have to affect the quality of your output." Applied to coding: AI That Works "Applying 12-factor agents principles to AI coding" https://www.youtube.com/watch?v=qgAny0sEdIk.

### 2. Advanced Context Engineering for Coding Agents (ACE-FCA, Aug 2025)
Talk at YC https://hlyr.dev/ace ; write-up https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md ; blog https://www.humanlayer.dev/blog/advanced-context-engineering. Thesis: brownfield coding works with today's models if you obsess over context. Key technique family: **"frequent intentional compaction"** — design the whole workflow around keeping context utilization ~40-60%; distill searches/logs/blobs into structured markdown artifacts; optimize context for correctness, completeness, size, trajectory (worst failures in order: incorrect info, missing info, noise). **Subagents are for context control, not role-play** ("not about playing house and anthropomorphizing roles"). Claim: Claude Code on a 300k-LOC Rust codebase (BAML), 35k LOC shipped in ~7 hours with the maintainer.

### 3. Research -> Plan -> Implement (RPI) and its successor QRSPI
The ACE workflow: **Research** (understand codebase/data flow; subagents do the grep/read), **Plan** (exact files/edits, precise verification per phase), **Implement** (phase by phase; compact status back into the plan file after each verified phase; only implement needs a worktree). Original prompts lived in the (now deprecated) humanlayer/humanlayer repo: `.claude/commands/research_codebase.md`, `create_plan.md`, `implement_plan.md`, with a `thoughts/` directory tool for sharing the markdown. Follow-ups: "No Vibes Allowed — Solving Hard Problems in Complex Codebases" https://hlyr.dev/nva (Nov 2025); "Everything We Got Wrong About RPI" https://hlyr.dev/qrspi-mlops / https://www.youtube.com/watch?v=YwZR6tc7qYg (Mar 2026). Failure modes found at scale (per Alex Lavaee's summary https://alexlavaee.me/blog/from-rpi-to-qrspi/): instruction-budget overflow (~150-200 instructions before models silently drop steps), magic-word dependency, and the "plan-reading illusion" ("A 1,000-line plan contains as many surprises as 1,000 lines of code"). QRSPI = Questions, Research, (design discussion, Structure outline), Plan, Implement, PR — more alignment phases before code, fresh contexts under 40%, subagents as "context firewalls." The "Why Software Factories Fail" part 2 four-phase model (product review -> architecture -> program design -> vertical slices) is the current form.

### 4. Ralph loops
Geoff Huntley's "Ralph Wiggum as a Software Engineer" (https://ghuntley.com/ralph/): `while :; do cat PROMPT.md | npx --yes @sourcegraph/amp; done` — an agent in an infinite loop over a declarative spec, one context window per iteration. Dex popularized/analyzed it: "A Brief History of Ralph" https://www.humanlayer.dev/blog/brief-history-of-ralph ; AI That Works episode https://www.youtube.com/watch?v=fOPvAPdqgPo ; YC Agents Hackathon project repomirror (ported BrowserUse to TS overnight) https://github.com/repomirrorhq/repomirror ; Dev Interrupted podcast "Ralph, RPI, and escaping the Dumb Zone" https://linearb.io/blog/dex-horthy-humanlayer-rpi-methodology-ralph-loop ; Matt Pocock livestream https://www.youtube.com/watch?v=NKu3T9FUjmU. Lessons: ruthless context resets; small nightly iterations beat huge overnight PRs; "overbaking" produces emergent weirdness; "a dumb model writes the code, a smart model checks it." Anthropic ships a ralph plugin: https://github.com/anthropics/claude-code/tree/main/plugins/ralph-wiggum.

### 5. Harness engineering / CLAUDE.md
"Skill issue: harness engineering for coding agents" https://www.humanlayer.dev/blog/skill-issue-harness-engineering-for-coding-agents — "It's not a model problem. It's a configuration problem." Surfaces: CLAUDE.md (<60 lines), MCP vs CLI, skills for progressive disclosure, subagents for context control, hooks for verification, backpressure that surfaces only errors. "Writing a good CLAUDE.md" https://www.humanlayer.dev/blog/writing-a-good-claude-md. Note the tension with WSFF part 1 (harness raises the floor, not the ceiling) — both are his positions: harness for reliability, humans + planning for design quality.

### 6. Why Software Factories Fail (Jul 2026) — see the three per-post files
Keynote https://www.youtube.com/watch?v=Ib5GBkD555M ; canonical md https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/wsff.md. Part 1 diagnosis (RL can't reward maintainability), part 2 prescription (four alignment phases, vertical slices, read the code, 2-3x not 100x), part 3 measurement (SlopCodeBench). ## How the pieces fit together (our read)
12FA gives the runtime principles (stateless reducer, own context/control flow, humans via tool calls). ACE/RPI/QRSPI give the per-task workflow (research -> plan -> implement with compaction and human gates). Ralph gives the outer loop for long-running/unattended work (fresh context per iteration, declarative spec). WSFF sets the policy limits (humans read code; plan at product/architecture/program-design level; vertical slices; measure maintainability with checkpointed evals). Harness-engineering posts give the Claude Code configuration surface (CLAUDE.md, skills, hooks, subagents).
